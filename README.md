# Joberti — тренажёр подготовки к собеседованиям

[![CI](https://github.com/ipostatos/joberti/actions/workflows/ci.yml/badge.svg)](https://github.com/ipostatos/joberti/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Персональный тренажёр подготовки к техническим и продуктовым собеседованиям:
маршрут обучения, теория, словарь, библиотека проверенных материалов, тесты с
интервальным повторением, mock interview, практические кейсы, английский для IT
и честная оценка готовности.

Telegram-бот + Telegram Mini App + необязательный сервис синхронизации.
В коде и документации продукт называется **Interview Trainer**, в Telegram он
живёт как **[@Jobertibot](https://t.me/Jobertibot)**.

**Четыре наполненных трека:**

| Трек | Вопросы | Уроки | Термины | Mock | Кейсы | Шаги плана |
|---|---:|---:|---:|---:|---:|---:|
| Junior SEO Specialist | 120 | 28 | 111 | 46 | 12 | 24 |
| QA Engineer (платежи) | 124 | 20 | 54 | 29 | 8 | 22 |
| Technical Engineer | 129 | 21 | 86 | 33 | 8 | 22 |
| DevOps / Platform Engineer | 108 | 21 | 61 | 26 | 8 | 22 |

Плюс сквозной раздел **«Английский для IT»** — один на все треки.

---

## 1. Что это

Продукт отвечает на вопросы, которые встают перед человеком, готовящимся к
конкретной вакансии:

* что от меня требуют и чего мне не хватает;
* с чего начать и что делать сегодня;
* насколько я на самом деле готов;
* успею ли я к дате собеседования.

Это учебная система, а не набор тестов: каждый вопрос привязан к теме, теме —
к уроку, уроку — к шагу плана, а план — к требованиям вакансии.

## 2. Структура продукта

```
Главный экран
├── что делать сегодня          ← одно конкретное действие
├── процент готовности          ← и что именно его ограничивает
├── дни до собеседования        ← и дневная норма
└── слабые темы

Разделы                         (цифры — по всем четырём трекам)
├── План подготовки             90 шагов, зависимости, условия завершения
├── Учить                       90 уроков по 80 темам
├── Практика                    481 вопрос, 7 режимов, SRS
├── Mock interview              134 открытых вопроса, полная сессия
├── Кейсы                       36 практических разборов
├── Словарь                     264 термина, карточки, проверка
├── Библиотека                  219 материалов с проверенными ссылками
├── Английский для IT           фразы, слова, речь, письмо, ресурсы
├── Вакансия и разрыв           требования, статусы, доказательства
├── Мои истории                 30 шаблонов STAR
├── Профиль                     готовность по блокам, достижения, данные
├── История                     тесты, сессии, кейсы, график готовности
└── Поиск                       по всему контенту сразу
```

Всего 17 экранов Mini App.

## 3. Возможности MVP

**Обучение.** 90 уроков, 264 термина словаря, 219 материалов библиотеки со
ссылками на первоисточники (231 источник, все проверены). Каждый факт привязан
к источнику, ссылки проверяются автоматически.

**Практика.** 481 вопрос с разбором каждого варианта ответа, семь режимов:
быстрый тест, тренировка, финальный экзамен, повторение по SRS, работа над
ошибками, только слабые темы, по темам. Варианты перемешиваются.

**Интервальное повторение.** Система Лейтнера с шестью коробками. Работает не
только для тестов, но и для терминов, открытых вопросов, кейсов и английского.

**Mock interview.** 134 открытых вопроса с разбором: структура сильного ответа,
что упомянуть, тревожные сигналы, эталон, рубрика самооценки. Полная сессия
проходит блоки в порядке настоящего собеседования.

**Кейсы.** 36 практических разборов: сначала своя попытка, потом эталонный
порядок действий и самооценка.

**Английский для IT.** Сквозной раздел, общий для всех треков, пять вкладок:
64 фразы (тренировка спрашивает ситуацией по-русски, а не переводом), 76 слов
в обе стороны (EN → RU и RU → EN, у каждого направления своя коробка SRS),
23 дрилла на речь вслух, 40 письменных заготовок — из них 13 с разбором
(«что нашлось / чего не хватает и почему»), 14 внешних ресурсов с пояснением
зачем и как. Текст письма никуда не отправляется и не сохраняется.

**Честная готовность.** Пять взвешенных блоков и жёсткие ограничители.
Самооценка на процент не влияет.

**План к дате.** Дневная норма пересчитывается из реально оставшейся работы
всех типов, а не только из числа тестов.

**Синхронизация.** Прогресс между устройствами через Telegram-аккаунт.
Приложение полностью работает и без неё.

## 4. Архитектура

```
Telegram Bot (aiogram 3, long polling)
    │  launcher: /start /menu /track /help /stats /privacy
    │  fallback без Mini App: вопросы, ошибки, статистика прямо в чате
    ▼
Telegram Mini App (статические HTML/CSS/JS, без сборщика и без CDN)
    │  всё состояние в localStorage → работает офлайн
    ▼
Sync API (FastAPI + SQLite)  ← необязателен
       слияние без потерь, авторизация по HMAC initData
```

Источник правды контента — читаемые JSON в `data/`. Из них генерируется
`webapp/generated/content_core.js` и трековые файлы. CI падает, если сгенерированное отстало
от источника.

Подробнее: [ARCHITECTURE.md](ARCHITECTURE.md).

## 5. Быстрый запуск: Windows

```powershell
cd InterviewTrainerBot

python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\pip install -r api\requirements.txt

copy .env.example .env
notepad .env                          # вписать BOT_TOKEN

.\.venv\Scripts\python tools\build_webapp_data.py
.\.venv\Scripts\python tools\validate_content.py

.\.venv\Scripts\python bot.py
```

Mini App локально (в отдельном окне):

```powershell
cd webapp
python -m http.server 8080
```

Открыть `http://localhost:8080/index.html`. Вне Telegram приложение работает
как обычный сайт: синхронизация выключена, всё остальное доступно.

## 6. Быстрый запуск: Linux

```bash
cd InterviewTrainerBot

python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -r api/requirements.txt

cp .env.example .env && nano .env      # вписать BOT_TOKEN

.venv/bin/python tools/build_webapp_data.py
.venv/bin/python tools/validate_content.py

.venv/bin/python bot.py &
(cd api && ../.venv/bin/uvicorn app:app --host 127.0.0.1 --port 4200) &
(cd webapp && python3 -m http.server 8080)
```

## 7. Настройка BotFather

1. `/newbot` — получить токен, вписать в `.env` как `BOT_TOKEN`.
2. `/setprivacy` → **Enable**. Бот работает только в личных чатах.
3. `/setmenubutton` → URL вида `https://ваш-домен/index.html`.
4. `/setcommands`:

```
start - Начать и открыть тренажёр
menu - Что доступно в чате
track - Выбрать трек подготовки
help - Справка
stats - Статистика ответов в чате
privacy - Данные и приватность
```

## 8. Настройка Mini App

Каталог `webapp/` раздаётся как статика по **https** — Telegram не открывает
Mini App по http. Адрес указывается в `.env`:

```dotenv
WEBAPP_BASE=https://ваш-домен
```

Если адрес не https, бот сам переходит в упрощённый чат-режим и пишет об этом
в лог: лучше рабочий чат, чем кнопка, которая не открывается.

Пример конфигурации веб-сервера: [deploy/Caddyfile.example](deploy/Caddyfile.example).

## 9. Sync API

Нужен только для прогресса на нескольких устройствах. Приложение работает без

cd api

Токен API обязан совпадать с токеном бота — им проверяется подпись `initData`.

## 10. Формат контента

Всё содержимое — читаемые JSON в `data/`:

| Файл | Что |
|---|---|
| `tracks.json` | направления подготовки |
| `vacancies.json` | вакансия, требования, gap-анализ |
| `topics.json` | темы трека, признаки «обязательная» и «критическая» |
| `sources.json` | источники с URL и датой проверки |
| `lessons.json` | уроки |
| `glossary.json` | термины словаря |
| `library.json` | материалы для чтения |
| `questions.json` | вопросы теста |
| `mock_questions.json` | открытые вопросы интервью |
| `cases.json` | практические кейсы |
| `roadmap.json` | шаги плана подготовки |
| `stories.json` | шаблоны историй STAR |
| `achievements.json` | достижения |
| `english_phrases.json` | фразы для собеседования на английском |
| `english_vocab.json` | слова, тренируются в обе стороны |
| `english_drills.json` | дриллы на речь вслух |
| `english_writing.json` | письменные заготовки и задания с разбором |
| `english_resources.json` | внешние ресурсы по английскому |

Английские файлы — сквозные: пустой `track_ids` означает «во всех треках».

Форматы и правила: [CONTENT_GUIDE.md](CONTENT_GUIDE.md).

## 11. Как добавить новый трек

1. Добавить запись в `data/tracks.json` со статусом `draft`.
2. Добавить темы в `topics.json` с `track_id` нового трека.
3. Наполнить `lessons.json`, `questions.json`, `glossary.json`, `library.json`,
   `mock_questions.json`, `cases.json`, `roadmap.json`.
4. Добавить вакансию в `vacancies.json`.
5. Перевести трек в `active` и указать `vacancy_id`, `critical_topic_ids`
   и `self_assessment_areas`.
6. Пересобрать и проверить:

```bash
python tools/validate_content.py
python tools/build_webapp_data.py
python tools/generate_content_report.py --track <id>
```

Пока трек не переведён в `active`, приложение не показывает по нему процент
готовности — незаполненный банк не должен выдавать оценку.

## 12. Как добавить вопросы

Добавьте запись в `data/questions.json`:

```json
{
  "id": "q-technical-seo-025",
  "track_id": "redcore-junior-seo",
  "topic": "technical-seo",
  "question": "…",
  "options": ["…", "…", "…", "…"],
  "answer": 0,
  "explanation": "…",
  "why": ["Верно: …", "…", "…", "…"],
  "difficulty": 2,
  "source_refs": ["google-canonicalization"],
  "related_term_ids": ["t-canonical-url"],
  "related_lesson_ids": ["lesson-robots-sitemap-canonical"],
  "verification_status": "verified"
}
```

Валидатор проверит: уникальность id, ровно четыре варианта, диапазон `answer`,
соответствие длины `why`, существование всех ссылок, отсутствие дублей и
конфликтов, распределение позиции правильного ответа и то, что правильный
вариант не выделяется длиной.

## 13. Как проверить источники

```bash
python tools/audit_sources.py            # с сетью: реальные запросы
python tools/audit_sources.py --offline  # без сети: только метаданные
```

Скрипт не входит в обязательный набор CI: внешние сайты падают по своим
причинам, и красный CI из-за чужого таймаута обесценивает сигнал. Запускать
вручную перед релизом контента.

Если ссылка недоступна, поставьте ресурсу `verification_status: "needs_review"`
вместо того чтобы удалять или выдумывать замену.

## 14. Как запускать тесты

Одной командой — ровно то же, что гоняет CI:

```bash
bash run_all_checks.sh
```

Списки тестов внутри собираются **по каталогу**, а не перечислением: новый
`tests/test_*.py` или `webapp/_*_check.mjs` попадает в прогон сам. Перечисленный
руками список здесь уже однажды отстал от реальности.

По отдельности:

```bash
# Python
python tools/validate_content.py
python tests/test_content.py
python tests/test_sync.py       # включая паритет JS и Python
python tests/test_api.py
python tests/test_bot.py
python tests/test_security.py
python tests/test_writing.py    # разбор письменных заданий
python tests/test_load.py       # 10 параллельных пользователей

# Mini App (нужен только node, без npm)
node webapp/_srs_check.mjs
node webapp/_progress_check.mjs
node webapp/_readiness_check.mjs
node webapp/_sync_check.mjs
node webapp/_search_check.mjs
node webapp/_sw_check.mjs
node webapp/_nav_check.mjs
node webapp/_writing_check.mjs

# Сгенерированные данные не отстали от источника
python tools/build_webapp_data.py --check
```

На Windows разбор контента запускать с `PYTHONIOENCODING=utf-8` — иначе cp1251
падает на символах IPA и стрелках.

## 16. Приватность

Прогресс хранится на устройстве. При включённой синхронизации копия лежит на
сервере и привязана к идентификатору Telegram, подтверждённому подписью.
Личность берётся только из подписанного `initData`, никогда из тела запроса.

Данные не передаются третьим сторонам, рекламы и трекеров нет. Сброс прогресса
удаляет данные и на устройстве, и на сервере.

Подробнее: [PRIVACY.md](PRIVACY.md).

## 17. Ограничения MVP

Честный список того, чего продукт не делает:

* **Не оценивает свободный текст ответа.** Без настоящей языковой модели такая
  оценка была бы имитацией: подсчёт совпадений слов легко обмануть, а
  пользователь принял бы результат за объективный. Вместо этого — разбор,
  эталон и рубрика самооценки, а в готовность идёт только подтверждённая
  повтором самооценка.
* **Четыре трека.** Трек получает процент готовности только в статусе `active`;
  пока банк не набран, приложение честно не показывает оценку.
* **Английский не входит в процент готовности.** Он идёт в дневную цель и в
  серию, но не в оценку готовности к вакансии — это намеренно.
* **Один язык интерфейса.** Русский; архитектура i18n позволяет добавить
  PL и EN.
* **Нет голосового ввода и распознавания речи.**
* **Нет импорта вакансии по ссылке.** Вакансия описывается в `data/`.
* **Нет серверной проверки прогресса.** Сервер хранит то, что прислал клиент:
  подкрутить свой процент технически возможно. Продукт помогает готовиться,
  а не выдаёт сертификат.
* **Бэкапы лежат на той же машине.** Для защиты от потери диска нужен внешний
  экземпляр.
* **Достижения не участвуют в расчёте готовности** — это намеренно.
