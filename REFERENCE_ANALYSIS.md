и решения о переиспользовании. Референс не менялся ни одним действием.

## 2. Где живёт новый проект и почему именно там

Новый проект: `C:\Users\user\Desktop\InterviewTrainerBot`.

Формально ТЗ просило создать sibling рядом с `ISSA_bot`, то есть внутри
`Desktop\ISSA\`. Это решение было сознательно изменено: любая запись внутри
`Desktop\ISSA\` — это запись в дерево, принадлежащее защищённому проекту,
и один неверный glob (`ISSA/**`) затронул бы обе стороны. Каталог верхнего
уровня `Desktop\InterviewTrainerBot` даёт ту же «соседскую» роль и при этом
физически исключает пересечение путей. На момент создания каталога не
существовало, ничего не перезаписывалось.

## 3. Что переиспользовано концептуально

Скопированных «как есть» файлов нет: каждый модуль переписан под предметную
область собеседований, с собственными ключами хранилища и собственным API.
Переиспользованы именно инженерные решения.

### 3.1 Дизайн-система (`webapp/theme.css`)

Идея: один CSS-файл с токенами, привязанными к переменным темы Telegram
(`--tg-theme-*`) и с фолбэком под светлую/тёмную схему. Компоненты — карточка,
строка-карточка, кнопка, шкала, чип, кольцо прогресса, плитка иконки.

Что взято: структура токенов, приём `color-mix(in srgb, var(--tone) 16%, transparent)`
для мягких подложек иконок, кольцо готовности на `conic-gradient` без SVG,
светлый фолбэк через `@media (prefers-color-scheme: light)`.

Что изменено: убраны морские акценты и медальоны с «золото/серебро/бронза» в
их игровом виде, добавлены токены статусов gap-анализа (`confirmed`, `partial`,
`learning`, `not_started`), нейтральная профессиональная палитра, компоненты
`step-card` (шаг плана), `rubric`, `req-row` (требование вакансии).

### 3.2 SRS-ядро (`webapp/srs.js`)

Идея: Leitner-коробки `0..5`, чистая функция перехода `nextState(prev, correct, now)`,
отделённая от хранилища ради тестируемости; `pickDue` приоритизирует сильнее
просроченные и низкие коробки; невиданный элемент считается «пора учить».

Что взято: сигнатуры API, чистое ядро, интервалы как массив, экспорт под
Node для проверок.

Что изменено: ключ `interview_srs_v1`; SRS обслуживает не только тесты, но и
термины словаря, mock-вопросы и кейсы — идентификаторы префиксуются типом,
статистика считается по типам; добавлен `stateMap()` для readiness.

### 3.3 Прогресс и мотивация (`webapp/progress.js`)

Идея: дневная цель, «бережный» streak с одной заморозкой подряд, карта
активности по дням для heatmap, чистое ядро `nextStreak`.

Что взято: механика streak с ровно одной заморозкой, хранение последних N дней,
`dayKey`/`dayDiff` на локальных датах.

Что изменено: ключ `interview_progress_v1`; «действием» считается не только
ответ на тест, но и карточка термина, mock-вопрос и шаг кейса; дата экзамена
переехала в `interview_exam_date_v1` и, в отличие от референса, **входит в
sync-контракт** (в референсе она была device-local, потому что merge её терял).

### 3.4 Расчёт готовности (`webapp/readiness.js`)

В референсе готовность — одна функция внутри `progress.js`: доля закреплённых
вопросов. Для тренажёра собеседований этого мало, поэтому вынесено в отдельный
модуль с пятью взвешенными блоками и жёсткими ограничителями (caps). Взята
только идея «слабая тема тянет общий процент вниз» и требование
воспроизводимости (чистые функции + одинаковый результат при одинаковом входе).

### 3.5 Синхронизация (`webapp/sync.js` + `api/`)

Идея, скопированная целиком на уровне архитектуры:

* аутентификация только через Telegram `initData`, проверка HMAC-SHA256 по
  схеме `secret = HMAC("WebAppData", BOT_TOKEN)`; `user_id` берётся исключительно
  из проверенной подписи, никогда из тела запроса;
* merge вместо перезаписи: «lost update» между двумя устройствами закрывается
  транзакцией `BEGIN IMMEDIATE` вокруг read-merge-write;
* **паритет merge-логики JS и Python** — одинаковые правила слияния на клиенте и
  сервере, и отдельная проверка в CI, что оба дают идентичный результат;
* полный фолбэк: нет initData / нет сети / ошибка API → приложение продолжает
  работать на `localStorage`;
* дебаунс-пуш и отправка при `visibilitychange → hidden`;
* rate-limit в памяти на пользователя, лимит размера тела, `busy_timeout` и
  `journal_mode=WAL` у SQLite.

Что изменено: состояние расширено (`srs`, `progress`, `profile`, `roadmap`,
`glossary`, `mock`, `cases`, `stories`); история попыток разделена на типы
(quiz / mock / case) и readiness-снимки; в merge добавлено правило для
самооценок mock/case (побеждает лучший подтверждённый результат, но
самооценка не «залипает» — см. `api/merge.py`).

### 3.6 Навигация и офлайн (`webapp/nav.js`, `webapp/sw.js`)

Взято: Telegram `BackButton` вместо закрытия webview, гард от двойного
срабатывания (`onClick` + `onEvent("backButtonClicked")` приходят вместе на
части клиентов), детерминированный возврат на `index.html` вместо ненадёжного
`history.back()`, хук `window.__navBack` для страниц с внутренними состояниями.
Service worker: network-first для кода и страниц (чтобы после деплоя не
залипала старая версия), stale-while-revalidate для статики, `/api/*` мимо кэша.

### 3.7 Иконки (`webapp/icons.js`)

Взят подход: inline-пути Lucide (лицензия ISC) без CDN, `stroke="currentColor"`,
гидрация по `data-icon`. Набор иконок пересобран под предметную область;
морские (`ship`, `waves`, `anchor`, `compass`) не переносились.

### 3.8 Инженерная обвязка

* Источник правды в читаемых файлах + генератор данных для Mini App +
  **проверка в CI, что сгенерированное не отстало от источника** (в референсе —
  `build_*_data.py` и сравнение `git diff`).
* Лёгкие проверки на чистом Node (`_*_check.mjs`) без npm-зависимостей: модули
  экспортируются и в браузер, и в `module.exports`.
* systemd-юниты с жёстким sandbox (`ProtectSystem=strict`, узкий
  `ReadWritePaths`, `SystemCallFilter=@system-service`).
* Секрет-скан в CI на формат токена Telegram и проверка, что `.env` не в индексе.
* Разделение `DEPLOY.md` / `DEPLOY_API.md`, отдельный `smoke.sh`.

## 5. Риски, найденные при изучении, и что с ними сделано

| Риск в референсе | Как учтено здесь |
|---|---|
| Дата экзамена device-local, потому что merge её молча стирал | Дата включена в контракт merge явным полем и покрыта тестом паритета |
| `readiness` возвращала честный процент даже на пустом банке | Черновой трек (`draft` / `coming_soon`) вообще не получает readiness; caps ограничивают процент при непокрытых блоках |
| Готовность = только доля закреплённых вопросов | Пять блоков с весами + ограничители; самооценка не может сама поднять процент |
| Логика merge продублирована в JS и Python вручную | Тот же приём (дублирование ради офлайна), но с обязательным тестом паритета на общих фикстурах |
| Кэш service worker мог «залипнуть» после деплоя | Сразу network-first для кода и страниц + проверка полноты списка ассетов в CI |
| Секреты в общем `.env` для бота и API | Сохранено (одна машина, один токен), но API читает `.env` только на предмет `BOT_TOKEN` и никогда не логирует `initData` |

## 6. Как обеспечена изоляция

1. Перед началом снят baseline референса: `HEAD`, `git status --porcelain=v1 -uall`,
   SHA-256 от `git diff` и `git diff --cached`, число файлов.
2. Рабочий каталог всех write-операций — только `Desktop\InterviewTrainerBot`.
   Ни одна команда записи не выполнялась с путём внутри `Desktop\ISSA`.
3. Никаких генераторов, миграций, сборок и тестов внутри референса не запускалось.
4. Новый проект — собственный `git init`, истории не связаны, `.git` не копировался.
5. CI нового проекта работает только со своим репозиторием и не обращается к
   референсу ни по одному пути.
6. По завершении baseline сверяется повторно; результат сверки — в финальном отчёте.
